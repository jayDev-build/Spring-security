# Spring Security Learning Project

This repository contains a Spring Boot application created to learn and understand the core concepts of Spring Security.

## What has been covered so far?

### 1. Basic Setup & Default Security
By simply adding the `spring-boot-starter-security` dependency to `pom.xml`, Spring Boot automatically secures all HTTP endpoints. 
- It generates a default login page.
- It provides a default username (`user`) and a randomly generated password printed in the console on startup.

### 2. Session Management
Spring Security creates and manages sessions for authenticated users.
- In `HelloController.java`, the endpoint `/` demonstrates how to retrieve the current session ID using `request.getSession().getId()`.
- Spring Security uses a cookie named `JSESSIONID` to track the user's session.

### 3. CSRF (Cross-Site Request Forgery) Protection
CSRF is an attack that forces an end user to execute unwanted actions on a web application in which they're currently authenticated.
- **Spring Security enables CSRF protection by default.**
- Because of this, while GET requests (like fetching the list of students) work seamlessly, state-changing requests like POST, PUT, DELETE (e.g., adding a new student) will be blocked with a `403 Forbidden` error unless a valid CSRF token is provided.
- **How it works:** The server generates a unique CSRF token for the session. Any state-changing request must include this token.
- In `StudentController.java`, the `/student/logout` endpoint returns the `CsrfToken` object so you can see how the token is generated and structured. When testing POST requests (like adding a student via tools like Postman), you would first need to get this token and include it in your POST request header (e.g., `X-CSRF-TOKEN`).
- **Important Note for Testing:** The CSRF token you copied from your browser fails in Postman because the token is tightly bound to your specific browser session via a Session Cookie. To test in Postman, you must fetch the token directly within Postman and ensure Postman sends the returned `JSESSIONID` cookie with your subsequent POST request.

### 4. REST APIs & In-Memory Service
- `StudentController` provides basic REST APIs (`GET /student/` and `POST /student/`) to retrieve and add students.
- `StudentService` manages the data using a simple in-memory `ArrayList` to simulate a database.
- The `Student` model uses Lombok annotations (`@Builder`, `@Getter`, `@Setter`, etc.) to reduce boilerplate code like constructors, getters, and setters.

## How to Test the Endpoints
1. Run the application.
2. Look at the console to find the autogenerated Spring Security password (the username is `user`).
3. Open a browser and go to `http://localhost:8080/`. You will be redirected to a login page.
4. After logging in, you will see the greeting message and your current Session ID.
5. To test the `POST /student/` endpoint, you will need to fetch the CSRF token first using a tool like Postman, perform a Basic Auth login, and include the CSRF token in the headers of your POST request.
